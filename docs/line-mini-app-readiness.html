Close to ready. Mostly channel setup plus five contained code changes.

Do these first · must change

1

Create a new LINE MINI App channel under the same provider

Console only~1 hour

LINE's FAQ: LIFF apps on a LINE Login channel "can't be migrated to a LINE MINI App channel." User IDs are issued per provider, so the same provider keeps every existing Member.lineUserId valid. A different provider orphans every member row.

Do

Create the Mini App channel in the LINE Developers Console under the provider that owns today's LINE Login channel. Region: Thailand. Link the @mitrjourney Official Account. Anyone permitted can do this since 11 Mar 2026.

2

Support three LIFF IDs and three channel IDs

Small code change~half day

A Mini App channel contains Developing, Review and Published internal channels. Each has its own LIFF ID, channel ID and endpoint URL. The code has one build-time NEXT_PUBLIC_LIFF_ID and one LINE_LOGIN_CHANNEL_ID, so today it fits only one environment.

Do

Either run three deployments with their own env values, or add a per-environment selector. The repo's own skill note in .devin/skills/line-liff/SKILL.md already sketches a getLiffId() selector. Rename the channel-ID env var so it no longer says "LOGIN".

3

Upgrade @line/liff from 2.29.0 to 2.31.2

Deadline ~24 Nov 2026~1 hour + test

LINE deprecated 2.20.0 through 2.31.0 on 30 Sep 2026 for a security issue and will restrict them "around November 24, 2026." This matters even if the Mini App move waits.

Do

Bump the dependency, then test login redirects. Version 2.31.2 changed how ? inside query values is restored. The app only strips code, state and liff.state, so this should be safe, but confirm on a device.

4

Publish privacy policy and terms pages

Content + 2 pages~1 day

The consent screen shows the privacy policy URL, and the Thai verification checklist lists it as required. The policy must name the company that handles user data. The registration form links to /terms, and no such route exists in the app today.

Do

Add /terms and /privacy pages, in Thai and English, and set both URLs in the channel's Basic settings.

5

Handle ID-token expiry

Medium code change1–2 days

LINE ID tokens "are valid for one hour." The hooks in lib/profile/use-member.ts, lib/api/bookings.ts and lib/api/purchases.ts resend the same token on every call. On a 401 they throw a "session could not be verified" error with no re-login. Mini Apps linger in LINE's multi-tab view, so after an hour every booking action fails until a reload.

Do

Check liff.getDecodedIDToken().exp before each call and re-login when stale, or exchange the ID token once for a signed server session cookie. The standalone path in lib/standalone-auth.ts already has that cookie machinery.

Already in place · works as-is

LIFF init is correctlib/liff/client.ts initializes once, client-side only, with withLoginOnExternalBrowser: true. Matches LINE's rule since Mini Apps opened to external browsers in Oct 2025.
Auth follows LINE's recommended modelClient sends the ID token as a Bearer header. lib/line/verify-id-token.ts verifies with LINE and checks audience, issuer and expiry. No API trusts a client-supplied user ID.
Safe areas handledViewport uses viewportFit: "cover". Top bar, bottom nav and global CSS use the safe-area insets. Covers Android edge-to-edge from Mar 2026.
Deep links will workPermanent links are the LIFF URL plus the page path. Next.js serves every path under the root endpoint, so a shared booking page resolves.
Only safe LIFF APIs usedLogin, logout, ID token, and one openWindow call guarded by isInClient. Nothing that breaks outside LINE.
Payment method is allowedPromptPay slip upload counts as an "other payment method," available in all regions. In-app purchase is Japan-only and not required.

Strongly advised

A

Loosen the login wall

Medium code change

The shell layout blocks every page, including about, contact and the schedule, behind LINE login and full registration. LINE's external-browser guidance says the service should work "without requiring LINE Login" for non-LINE users. The Policy says registration should be required only where it is needed for points or purchases.

Do

Keep home, schedule, instructors, about and contact public. Gate booking, profile and payments.

B

Measure performance and match the loading icon

Unverified

LINE requires a Lighthouse performance score of 50 or above, measured on production while logged out. Nothing in the repo shows this has been checked. LINE also recommends its 30×30 SVG spinner, centered, in place of the app's "Connecting to MiTR..." text spinner.

Do

Run Lighthouse against the Published URL with LINE Login disabled, and swap the spinner.

Verified status in Thailand · business step

Unverified Mini Apps are fully usable in production. Verification is optional, and in Thailand it is gated on becoming a certified provider through LINE for Business Thailand.
